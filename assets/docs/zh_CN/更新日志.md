# 更新日志

## 0.6.2

### 新增

- 新增网盘传输能力策略：对暂不支持上传的挂载在上传前直接拦截并提示，避免进入传输流程后才失败。
- 百度网盘等不支持直接下载的挂载会在下载前提示，下载入口同步标注“推荐 Motrix Next”。

### 优化

- 首页网盘列表改为直接读取已配置挂载，避开较慢的存储列表接口，打开思盘和文件管理首页更快显示。
- 网盘目录切换增加轻量加载动画，Dock 文件树会在正在打开的位置显示，文件管理页面加载列表时也会给出状态反馈。
- 根目录列表优先读取 `config.json` 中的挂载配置，仅在本地配置不可用时回退到文件列表接口，减少重启后的等待时间。

### 修复

- 修复挂载盘音视频文件点击播放被 companion `data-href` 链路提前截获的问题；音视频改回主动解析播放地址，阅读类文件保留稳定的 `/p/<path>` 预览链接。
- 修复不支持上传或直接下载的挂载缺少前置提示的问题，Dock 文件树、文件管理器和右键下载入口都会在开始前给出明确反馈。

- 修复 123Pan 下载双地址链路：当 `yun.123pan.com` 返回的解码跳转因 Referer 敏感响应 403/50001 失败时，会继续回退到配套的 `api.123278.com` / `www.123pan.com` 流程。

## 0.6.0

### 新增

- 新增 `/` 命令插入入口：在编辑器输入 `/` 后选择“思盘”，可搜索或浏览思盘文件树并插入文件链接。
- `/` 插入复用右键菜单的复制链接逻辑：图片插入 Markdown 图片，音频插入 `<audio>`，视频插入 `<video>`，其它文件和文件夹插入稳定的 `siyuan://plugins/siyuan-cloud/open?path=...` 链接。
- 新增索引建立入口：文件管理器“更多”菜单和 Dock 工具页都可触发建立索引；搜索无结果时会提示先建立索引，耗时取决于文件数量。
- 新增 GitHub Releases 运行时驱动：支持按仓库结构浏览 Release 资产、README/LICENSE、源码包和全部版本，可配置 GitHub Token 与代理地址。
- 新增中英文 GitHub Releases 驱动说明。
- 新增飞书文档同步脚本 `pnpm docs:feishu` 和 `release:with-docs` 发布入口，README、API、更新日志和驱动说明可从本地 Markdown 同步到飞书。

### 优化

- 精简搜索索引进度存储和执行路径：建立索引在后台执行，进度直接记录到运行时状态，并支持停止、清空和查询进度。
- 优化预览与文档插入格式：图片、音频、视频保留可直接预览/播放的资源链接；PDF、EPUB、TXT、压缩包、普通文件和文件夹统一使用 `siyuan://` 打开思盘。
- 明确 `/` 插入支持格式：图片包含 `jpg/tiff/jpeg/png/gif/bmp/svg/ico/swf/webp/avif`，音频包含 `mp3/wav/aac/m4a/flac/ogg`，视频包含 `mp4/mkv/avi/mov/rmvb/webm/flv/m3u8/m4v`，文本预览类包含 `txt/log/md/markdown/json/xml/yml/yaml/toml/ini/conf/js/ts/jsx/tsx/vue/css/scss/less/html/htm/go/py/java/rb/rs/php/c/cpp/h`；除图片、音频、视频外，插入文档时统一生成 `siyuan://` 链接。
- 统一 FileTab、Dock、拖拽和 `/` 插入的链接生成入口，减少复制链接与插入链接之间的分叉。
- Dock 状态页文档入口切换为飞书 Wiki 链接，说明文档、API、更新日志和驱动说明直接在浏览器打开。
- 删除旧的打包文档清单和思源文档写入路径，运行时只读取生成的飞书文档链接，不再创建或更新思源笔记本文档。
- 前端请求增加轻量重试，遇到限流提示时会短暂等待后重试，减少偶发 TooManyRequests 失败。
- 内核状态读写增加限流重试，减少同步存储读写遇到 TooManyRequests 时的失败。
- 状态页和能力矩阵补入 `github_releases` 适配器信息，驱动列表只展示已经接入运行时的 GitHub Releases。
- 打包规则精简为只复制根目录中英文 README，不再把 `assets/docs` 整树打入插件包。

### 修复

- 修复 Docker 部署下无法验证和创建云盘挂载的问题，避免驱动测试阶段直接返回 `Auth failed [session]`。
- 修复搜索索引进度曾经写在 settings 字符串里的历史兼容问题，加载旧数据时会迁移到独立的 `index_progress` 运行时状态。

## 0.5.2

### 新增

- 文件管理器新增图片瀑布流视图，可在列表和图片视图之间切换，并紧凑显示图片文件名与大小。
- 文件管理器支持 Ctrl/Shift 多选文件，并新增 Ctrl+A、Esc、Delete、Enter 等键盘快捷键。
- 文件管理器支持将选中的多个文件批量下载或批量发送到 Motrix Next。
- 文件管理器和 Dock 文件树支持将文件拖入文档，直接插入链接。

### 修复

- 修复 S3 兼容存储预签名链接的 SigV4 query 排序：改用 AWS 字节序排序并保持 RFC 3986 编码输出，避免带 `response-content-disposition` 的中文文件下载链接触发 `SignatureDoesNotMatch` 403。
- 修复 S3 兼容存储上传生成 0KB 文件的问题：上传优先使用 OpenList `HttpDirect` 预签名 PUT 直传，回落路径改为明确的 base64 body，避免 multipart 在思源 JS kernel 中丢失文件内容。
- 修复音频文件拖入文档后点击播放失败的问题：音频现在插入为可直接播放的 `<audio>` 控件，不再落到浏览器无法识别的插件协议链接。
- 修复 WPS 云文档上传卡死问题：当前思源 JS kernel 暂不启用 WPS 上传，避免 base64 解码、校验和代理上传阻塞思源。

## 0.5.1

### 新增

- 新增 Motrix Next 下载投递：文件右键菜单可通过可配置的 Extension HTTP API 地址发送到 Motrix Next，内核转发避免浏览器 CORS 问题，API 密钥和思盘外部访问地址会保存到插件数据文件。
- 文件管理器新增干净的悬停式传输区域：把文件拖到右下角区域即可上传，并显示最近上传/下载的进度、成功和错误状态，平时不占用界面。

### 修复

- 修复内置传输流程：下载不再使用假的 1% 进度，改为真实流式进度；完成和错误状态会保留显示；内置下载限制并发，并在完成前写入临时文件。
- 修复 OpenList/AList 连接兼容：私网和本机挂载在思源阻止后端 SSRF 请求时保留前端直连路径，普通挂载继续使用标准 OpenList 兼容后端路径。
- 对齐 115 与 S3 下载语义：115 下载保持浏览器/播放器 `User-Agent` 一致；S3/Doge 下载改用后端 AWS 签名代理读取并支持 Range，避免脆弱的预签名跳转导致 403。
- 修复 115 播放请求头对齐问题：`/d` 和 `/p` 现在会把播放器/浏览器的 `User-Agent` 传入 115 Cloud / 115 Open 链接解析，并继续转发给上游下载直链，减少因请求头错位或旧直链导致的 `115cdn.net` 403。
- 修复 115 Open token 并发刷新过于频繁的问题：同一个挂载在并发 API 或 Range 请求撞到过期 token 时会共享一次刷新。
- 明确 115 Open 上游 `refresh frequently` 提示：界面会说明这是开放平台 token 刷新限频，并提示等待后重试或编辑现有挂载替换 token，不需要删除重建挂载。
- 修复挂载创建和更新的安全性：新增挂载时如果路径已存在会返回冲突，不再静默覆盖旧挂载；挂载增删改启停前也会先刷新最新配置再保存。
- 修复 S3 兼容存储中文名和特殊字符对象路径签名：签名前按 AWS RFC 3986 编码路径，避免上传和管理操作触发 `SignatureDoesNotMatch`。
- 修复伴侣插件文件链接和显式下载：PDF/EPUB/音频链接改用绝对插件地址，避免变成 `file:///plugin/...`；`/d` 响应会声明附件下载，下载动作也会临时绕开伴侣预览拦截。

## 0.5.0

### 新增

- 新增 WPS 云文档运行时驱动：按 OpenList `drivers/wps` 接入 Cookie 登录校验、Personal/Business 模式、根目录/群组列表、文件下载链接、统一 `/p` 代理读取、基础管理操作和容量详情；上传仍保持明确占位，并新增中英文 WPS 驱动说明。
- 补齐 WPS 云文档前端细节：驱动帮助入口现在直达 WPS 说明，Cookie 字段显示 WPS 专属说明而不再沿用 115 的二维码文案，挂载卡片也使用 WPS 专属图标。

### 修复

- 对齐 OpenListTeam/OpenList#2678 中覆盖更完整的 123Pan 上游修复：API 请求、网页 origin/referer 请求头和下载跳转 Referer 现在统一使用 `https://yun.123pan.com`，不再沿用 #2677 中 `api.123278.com` / `api.123pan.cn` 的 host 拆分方案。
- 对齐 Quark/UC 系列运行时细节：`use_transcoding_address` 默认值改回与 OpenList 一致的关闭状态，转码地址无可用链接时回退普通下载链接；列表请求会吸收并持久化上游刷新的 `__puus` / 转码场景 `__pus` cookie，空间详情补齐总量、已用和剩余容量；QuarkTV/UCTV 扫码时会把“用户未确认授权”识别为待确认状态并继续轮询；QuarkOpen 在开启在线 API 时会先刷新 `access_token`，并在 `app_id` / `sign_key` 留空时使用不默认展示的内置公参，上传凭证会稳定保存并复用 `user_id`，避免缺少用户标识时生成 proof 失败。
- 修复 Dock 驱动配置表单中的状态文本：驱动说明、扫码/短信提示和底部红色错误信息现在会对长内容自动换行，并且可以选中复制。
- 修复 189CloudPC / 189CloudTV 扫码登录细节：PC 扫码登录会在网页登录、取 UUID、轮询和换取 session 之间保留上游 cookie；PC 和 TV 扫码都复用统一的二维码状态机；TV 的 `qrCodeRollLogin()` / `QrCodeRollLoginFail` 会作为等待扫码状态处理，并显示干净提示，不再把上游原文直接露出。
- 补齐 189CloudPC 家庭云接入：PC session 刷新时会像 TV 驱动一样规范化家庭云根目录，并在 `type=family` 且 `family_id` 留空时自动读取家庭云列表回填 ID；同时更新 189Cloud 系列中英文说明，明确家庭云应使用 PC/TV 驱动。
- 修复并对齐 S3 兼容存储读取和管理链路：`/p` 代理继续使用插件内签名读取并转发 Range 请求，避免思阅/PDF.js 预览触发上游预签名 403；`/api/fs/link` 单独返回 OpenList 风格 GET 预签名链接；同时将 `force_path_style` 默认值对齐 OpenList 的关闭状态，列表分页、目录识别按 OpenList 处理，过滤目录 marker 对象，支持目录复制、移动、删除、重命名递归操作，默认目录占位文件保持 `.siyuan-cloud`。
- 修复阿里云盘开放平台等非强制代理挂载的播放路径：`/d` 下载入口现在按 OpenList 语义优先 302 到直链，`/p` 保持强制代理，避免普通视频被插件代理链路拖慢。
- 修复阿里云盘开放平台传给思播的播放地址：点击视频时优先通过 `/api/fs/other` 获取 `video_preview` 转码预览流并传入播放器，失败时再回退 `/d` 原文件直链。

## 0.4.0

### 新增

- 接入 `115 Open` 和 `115 Share` 运行时，并补齐 `115 Cloud`、`115 Open`、`115 Share` 挂载说明：115 Open 支持 token 刷新、浏览、读取、基础管理和空间详情，115 Share 按 OpenList 保持只读分享挂载。
- 补齐 `115 Cloud` / `115 Share` 挂载表单扫码入口：可直接刷新二维码、轮询扫码状态，并在确认后自动换取 `cookie`。

- 新增 DogeCloud 挂载说明，记录 OpenList `Doge` 驱动通过多吉云临时密钥 API 换取 S3 凭证的机制，以及当前运行时仍按通用 S3 处理的边界。

### 修复

- 修复 `115 Cloud` 播放/下载链接解析偶发提示“提取码不能为空”的问题：`downurl` 请求已对齐 OpenList 115 驱动，将加密后的 `data` 字段作为 URL 编码表单发送，避免 `+` 被当作空格；`115 Share` 的 115 表单请求也使用同一编码方式。
- 修复 115 扫码登录来源选择、状态识别和保存流程：`qrcode_source` 会稳定显示并用于 OpenList 风格的最终扫码确认接口，扫码状态兼容数字与字符串确认值；点击“添加”时若仍处于二维码会话，会先确认扫码并写回 `cookie`，避免一直提示等待扫码或在思源 v3.7.0 下报参数错误。
- 修复思源 v3.7.0 下 OpenList/AList 本机和内网挂载不可用的问题：对 `127.0.0.1:5244`、`192.168.x.x:5244` 等私网地址增加桌面端前端直连路径，同时保留标准后端 OpenList 兼容驱动路径。
- 修复 OpenList/AList 私网直连挂载的媒体预览：打开文件时再通过 `/api/fs/get` 懒解析可播放链接，避免继续退回后端 `/p` 代理地址。
- 修复 FileTab 和 Dock 文件树点击媒体文件只提示下载的问题：音频/视频会优先打开媒体播放器，未接入播放器时使用内置预览。
- 修复复制文件链接：思盘文件路径会复制为可读的 `siyuan://plugins/siyuan-cloud/open?path=...` 链接，点击后回到思盘并高亮目标行。
- 修复 OpenList/AList 服务地址规范化：挂载配置中的 `/admin` 和 `/@manage` 会自动剥离，避免把后台页面地址当作 API 基础地址。
- 修复 OpenList/AList 文件读取能力：补全相对 `raw_url`，并返回 OpenList 风格 link 数据，用于 `/d`、`/p`、压缩包和下载流程。
- 修复打包文档内部链接：驱动说明中的 `[[...]]` 现在也会转换成真实思源文档引用，不再只在 README 中生效。

### 已知限制

> [!WARNING]
> 思盘当前仍是运行在思源内的兼容运行时，不是公网独立 OpenList 服务。

- 当前仍是 OpenList 兼容的思源 kernel runtime 子集，不是完整 OpenList 服务。
- 任务接口已对齐 OpenList 形态，但真实异步队列、取消传播、重试调度和进度上报仍待实现。
- 搜索使用本地持久索引，还不是完整 OpenList search backend 矩阵。

- RAR/7z/ISO reader 仍是占位，需要等 reader、许可证、打包路径和 fixture 都明确后再接入。
- `/ae` 压缩包内媒体目前偏向 entry 提取，不等同于普通 `/p` 的可 seek 流式播放。
- 离线下载工具和真实 189/189PC CAS rapid-upload 仍需要继续迁移。
